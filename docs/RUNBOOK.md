# Operator runbook — windows-cluster-controller

> Day-2 operations for an already-set-up controller.

## Daily

Nothing required. MeshCentral runs unattended. The Announcer keeps host discovery working. Backups are NOT automatic; see Weekly.

## Weekly

**Take a backup.** Schedule via Task Scheduler or run manually:

```powershell
.\scripts\Backup-Controller.ps1
# default output: %ProgramData%\ClusterController\backups\controller-<hostname>-<utc>.zip
```

Recommended schedule (Task Scheduler XML excerpt; adjust user / paths):

```xml
<Triggers>
  <CalendarTrigger>
    <StartBoundary>2026-01-05T03:00:00</StartBoundary>
    <ScheduleByWeek>
      <DaysOfWeek><Sunday /></DaysOfWeek>
      <WeeksInterval>1</WeeksInterval>
    </ScheduleByWeek>
  </CalendarTrigger>
</Triggers>
```

Action: `pwsh.exe -NoProfile -File C:\Path\To\windows-cluster-controller\scripts\Backup-Controller.ps1 -StopService`

`-StopService` ensures a consistent snapshot if there are active sessions. Adds ~30s of MeshCentral downtime.

Rotate old archives: anything older than 30 days is safe to delete unless you're keeping point-in-time recovery for compliance reasons.

## Monthly

**Update MeshCentral** to pick up security fixes:

```powershell
.\scripts\Update-MeshCentral.ps1                    # latest
.\scripts\Update-MeshCentral.ps1 -TargetVersion 1.1.39   # pinned
```

The script backs up first, installs, health-checks, and auto-rollbacks on failure. The pre-update archive name + version are echoed at the end.

**Review the audit log** at `https://<controller>/admin` → Events. Any unfamiliar logins or unauthorized device adds warrant investigation.

## Quarterly

**Renew the TLS cert.** Self-signed certs expire after `tls.self_signed.valid_for_days` (default 825 days). For an early renewal:

```powershell
# 1. Backup
.\scripts\Backup-Controller.ps1

# 2. Force regeneration (the old cert is rotated; new cert gets a new thumbprint and is recorded in MeshCentral config.json)
Remove-Item Cert:\LocalMachine\My\<old-thumbprint>
pwsh -File src\Invoke-ClusterControllerSetup.ps1 -StartFromStage 7

# 3. Each host PC needs the new cert imported. Re-run host install.ps1 on each, or push the new cert via MeshCentral's group script execution.
```

For a CA-issued cert (`tls.mode=import`): renew with your CA, drop the new `.pfx` over the old one at `tls.import.pfx_path`, set `$env:CLUSTERCTRL_TLS_PFX_PASS`, re-run from Stage 7.

## Disaster recovery

**Controller died, restore on new hardware.**

1. Install Win11 Pro on the new PC. Set hostname to match the old controller (or update DNS to point `controller.lan` at the new machine).
2. `.\install.ps1 -ControllerHostname controller.lan -WriteConfig` — runs all 13 stages from scratch.
3. Once the new install reaches Verify=Pass, restore the most recent backup:
   ```powershell
   .\scripts\Restore-Controller.ps1 -ArchivePath <path-to-backup>.zip
   ```
   The restore stops MeshCentral, swaps in the old data dir (existing rotated to `.pre-restore.<utc>`), restarts.
4. Each host PC's MeshAgent will reconnect automatically — IF the cert thumbprint is preserved by the restore (it is, since `meshcentral-data` is included).

If you only have the data dir backed up (no full archive), you can hand-place it under `%ProgramData%\MeshCentral\meshcentral-data` and start MeshCentral; the controller will pick it up.

## Log locations

| What | Where |
|---|---|
| Setup script log | `%ProgramData%\ClusterController\logs\setup-<utc>.log` |
| MeshCentral runtime | `%ProgramData%\MeshCentral\meshcentral-data\mesherrors.log` (errors) and `mesh.log` (general) |
| MongoDB (when used) | `%ProgramData%\ClusterController\mongo\log\mongod.log` |
| Announcer service | NSSM redirects stdout to `%ProgramData%\ClusterController\bin\announcer.out` (configure if needed) |
| Windows event log | Application log; filter by source `MeshCentral` |

## Common operator commands

```powershell
# All cluster services at a glance
Get-Service MeshCentral, ClusterAnnouncer, MongoDB -ErrorAction SilentlyContinue

# Restart MeshCentral (no data loss)
Restart-Service MeshCentral

# Verify the announcer payload hosts will see
Invoke-WebRequest http://127.0.0.1:8765/.well-known/cluster-controller | ConvertFrom-Json

# Re-run only the Verify stage to refresh setup-summary.txt
pwsh -File src\Invoke-ClusterControllerSetup.ps1 -StartFromStage 13

# Inspect run state
Get-ItemProperty HKLM:\Software\ClusterController

# Manually trigger an agent bundle re-export (e.g., after group changes)
pwsh -File src\Invoke-ClusterControllerSetup.ps1 -StartFromStage 10
```

## Security notes

- The admin password generated by Stage 10 lives in `%ProgramData%\ClusterController\admin-bootstrap.txt` with strict ACL (LocalSystem + Administrators only). **Read it once, save to your password manager, delete the file.**
- The TLS PFX (if you use `tls.mode=import`) MUST NOT be checked into source. The password is in an env var named by `tls.import.pfx_password_envvar`.
- MongoDB (if configured) binds 127.0.0.1 only. Don't change `db.mongodb.bind` without understanding the consequences.
- The Announcer serves on port 8765 over plain HTTP because the host's discovery has no cert pinning yet. The content is metadata-only (hostname + IP + ports). If your LAN is hostile, switch the Announcer behind HTTPS by editing `bin\announcer.ps1` to use an HttpsListener configuration.
